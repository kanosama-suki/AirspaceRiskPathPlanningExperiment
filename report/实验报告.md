# 城市空域风险路径规划对比实验报告

**当前数据范围：** 本地 60 s、 本地 180 s 的 A/B 任务 1/2/3，以及服务器 600 s 的 A/B 任务 1/2。

> 历史说明：本文记录旧版固定任务 1/2/3 与 60/180/600 s 预算矩阵，用于保留已完成工作。它不对应当前的 S/M/L 百分位路线设计，不得把本文排名冒充新一轮多路线正式实验结果。当前 S/M/L 正式矩阵在预算校准完成后另写报告。

## 1. 实验目的

本实验比较 A*、RC-A*、RiskA*、RRT* 和 Informed RRT* 在城市低空风险地图上的规划表现。五种算法共用场景、起终点、风险矩阵、碰撞规则和路径评价器，观察算法表现如何随城市形态、飞行任务和时间预算变化。
回答以下问题
1. 最优算法会不会随不同的情况发生变化
2. 每种算法在不同的情况下表现如何
3. 给出在不同情况下的算法选择建议
4. 结论在两套地图上是否一致，为什么

## 结论

1. 在当前已完成的 60 s 和 180 s 和600 s中，不变。
2. A* 适合较快完成较简单的任务；RC-A* 在相同成功条件下综合代价略低。
3. 需要稳定路径时优先 RC-A*；需要较短响应时间且任务较简单时可选择 A*；RiskA*、RRT* 和 Informed RRT* 需要更多实验场景和数据
4. 一致。地图复杂度主要影响运行时间和采样算法可行率，没有改变当前条件中结论。

## 2. 实验对象和条件

### 2.1 城市场景

场景 A 使用深圳南山真实 OSM 建筑和人口数据；场景 B 使用随机生成的城市。两套地图采用相同的风险模型和规划参数，建筑与人口分布不同。

| 项目 | A：真实深圳南山 | B：随机生成城市 |
|---|---:|---:|
| 建筑数量 | 546 栋 | 219 栋 |
| 地面建筑覆盖率 | 21.5406% | 26.9581% |
| 建筑体素数 | 2,921,211 | 8,416,476 |
| 可飞行体素数 | 84,918,789 | 79,423,524 |
| 风险矩阵形状 | `(1200, 1200, 61)` | `(1200, 1200, 61)` |

地图平面范围为 `1200 m × 1200 m`，底层栅格分辨率为 `1 m`，高度范围为 `30–90 m`，共 61 层。规划节点按 `10 m` 步长离散。索引为 `[i,j,h_idx]`，对应世界坐标 `(x,y,z)=(i,j,30+h_idx)`。

### 2.2 飞行任务

任务 1、2 的端点来自场景配置表 2。任务 3 是在实验配置中增加的跨高度任务，用于检查三维规划和高度层风险查询。

| 任务 | 起点 | 终点 | 说明 |
|---|---|---|---|
| 1 | `(100, 1100, 30)` | `(1100, 100, 30)` | 30 m 同高度飞行 |
| 2 | `(900, 1150, 30)` | `(10, 10, 30)` | 第二组同高度端点 |
| 3 | `(100, 1100, 30)` | `(1100, 100, 90)` | 从 30 m 跨高度飞至 90 m |

任务 3 仅覆盖实验配置中的端点，不修改场景输入文件。A、B 两个场景的任务 3 起终点均为空中可用位置。

### 2.3 风险数据和评价指标

遮蔽系数 `P_s` 使用二维 `building_footprint`，按 21×21 中心窗口计算，边界使用 reflect。风险矩阵 `R` 的建筑体素保留为 `NaN`；建筑碰撞检查使用 `building_mask`。归一化基准 `R_norm` 取全量有限值均值和精确中位数中的较小值。

所有规划器的路径都由公共评估器按 `1 m` 间距重采样。评估器检查节点碰撞、边碰撞、NaN 命中和水平转角约束，再计算路径长度、风险积分和综合代价：

```text
t_hour = distance / (V_CRUISE × 3600)
composite_cost = ALPHA1 × distance_cost + ALPHA2 × normalized_risk_cost
```

实验使用 `V_CRUISE=20 m/s`、`ALPHA1=0.4`、`ALPHA2=0.6`。论文 B 表格另列 M350 速度 23 m/s；本工程按任务书和 config 的 20 m/s 执行。`risk_expected` 表示沿路径累计的未归一化风险积分，`composite_cost` 由公共评估器统一计算。

风险校验中，窗口和探针最大相对误差约 `3.17e-5`，按工程容差决策继续使用；它高于 README 的 `1e-5` 严格逐点阈值。B 场景 summary 中位数与精确中位数相差约 `1.1447%`，原因是 summary 使用 log 直方图估值；实验仍使用精确有限值统计得到的 `R_norm`。这些口径已记录在 `report/assumptions.md`。

## 3. 实验步骤

1. **读取场景与参数。** 从只读场景配置加载 A/B 地图、建筑掩码、人口密度、任务端点和风险参数。
2. **生成并校验风险矩阵。** 计算二维 `P_s` 和三维 `R`，检查建筑 NaN、窗口、探针和全局统计。
3. **验证公共规划层。** 用小地图测试坐标映射、26 邻域、碰撞、转角和路径指标；再用真实 R 检查数据流。
4. **运行五种算法。** 在相同场景和任务下按指定 seed、预算执行。A*、RiskA*、RC-A* 使用 seed `114514`；RRT* 和 Informed RRT* 使用 seed `0–19`。
5. **统一复核结果。** 对每条返回路径重新检查碰撞、NaN 和转角，并用公共评估器计算长度、风险积分和综合代价。
6. **汇总原始记录。** 失败和超时记录保留在 `experiments/raw/`；综合代价排名只使用 `success` 运行。采样算法的 `timeout_with_solution` 仍单独记录为超时。

## 4. 实验操作

正式实验配置位于 `experiments/configs/formal.toml`，快速冒烟配置位于 `experiments/configs/smoke.toml`，两者使用独立输出目录。本地结果按预算分开保存：60 s 写入 `experiments/raw/60/`，180 s 写入 `experiments/raw/180/`；服务器 600 s 批次已复制到本地 `experiments/raw/600/`。任务 3 使用独立 run id，原有任务 1/2 数据没有覆盖。

```powershell
# 60 秒：A/B 的任务 3，8 个进程
python -m experiments.run --profile short_60s --workers 8 --scenes A B --missions 3 --run-id local_60s_task3_8p

# 180 秒：A/B 的任务 3，8 个进程
python -m experiments.run --profile local_180s --workers 8 --scenes A B --missions 3 --run-id local_180s_task3_8p
```

60 s 的任务 1/2 历史记录使用 4 个 worker；后来追加的任务 3 使用 8 个 worker。180 s 的任务 1/2 使用 8 个 worker，任务 3 也使用 8 个 worker。每次运行的 worker 数、executor、预算、配置哈希和 run id 都写在 JSONL 中。单次运行时间以算法自身运行时间字段为准，整批墙钟时间会随并发数和机器负载变化。

每行 JSONL 保存场景、任务、算法、seed、状态、路径长度、风险积分、综合代价、运行时间、展开或采样统计、首次可行时间、失败原因、配置哈希和路径合法性复核结果。

## 6. 结论（对应任务书第 4 节）

任务书规定：在同一场景、同一任务和同一预算下，路径综合代价最低者为该条件下的最优算法。下面的判断只使用已经返回 `success` 且通过统一合法性复核的运行；采样算法的 `timeout_with_solution` 路径单独报告，不直接和成功运行混合排名。

### 6.1 最优算法会不会随不同情况变化

在当前已经完整的 60 s、180 s 和 600 s 条件中，能够形成正式排名的条件，其最优算法都是 RC-A*：

| 预算 | 场景/任务 | 可形成排名的算法 | 最优算法 | 最低综合代价 |
|---|---|---|---|---:|
| 60 s | A/1 | A*、RC-A* | RC-A* | 573.1268 |
| 60 s | A/3 | A*、RC-A* | RC-A* | 573.3272 |
| 60 s | B/1 | A*、RC-A* | RC-A* | 578.4256 |
| 60 s | B/3 | A*、RC-A* | RC-A* | 573.3395 |
| 180 s | A/1 | A*、RC-A* | RC-A* | 573.1268 |
| 180 s | A/2 | RC-A* | RC-A* | 606.0220 |
| 180 s | B/1 | A*、RC-A* | RC-A* | 578.4256 |
| 180 s | B/2 | RC-A* | RC-A* | 613.4697 |
| 180 s | A/3 | A*、RC-A* | RC-A* | 573.3272 |
| 180 s | B/3 | A*、RC-A* | RC-A* | 573.3395 |
| 600 s | A/1 | A*、RC-A*、RiskA* | RC-A* | 573.1268 |
| 600 s | A/2 | A*、RC-A*、RiskA* | RC-A* | 606.0220 |
| 600 s | B/1 | A*、RC-A*、RiskA* | RC-A* | 578.4256 |
| 600 s | B/2 | RC-A*、RiskA* | RC-A* | 613.4697 |

因此，**在目前可正式排名的条件中，最优算法没有发生变化，均为 RC-A***。预算改变了可行性和可比较性：60 s 时 A/2、B/2 的图搜索结果还不完整，180 s 时 RC-A* 已完成两个任务，600 s 时 A* 也完成了 A/2，RiskA* 则在四个 600 s 条件中都返回了路径。预算增加带来了更多可比较结果，但没有改变最低综合代价的算法。

60 s 和 180 s 任务 3 均已完整。两个预算下 A*、RC-A* 都能完成 A/3、B/3，RC-A* 的综合代价略低于 A*；采样算法在 180 s 下仍未达到 80% 可行率。

### 6.2 每种算法在不同情况下的表现

**A*** 在任务 1、任务 3 以及 B/1 中可以较快完成，路径长度约为 1433–1446 m，综合代价约为 573–578。600 s 下它完成了 A/2，但 B/2 仍未在预算内完成，说明图搜索的运行时间会明显受到场景和任务结构影响。

**RC-A*** 在容易完成的条件下综合代价略低于 A*，例如 A/1 低约 `0.0007`，B/1 低约 `0.0013`。它的启发式需要计算当前节点到目标包围盒中的风险统计，但在 180 s 下已经完成 A/2、B/2，在 600 s 下四个任务均返回路径，因此在当前实验中兼顾了路径质量和较难任务的可行性。

**RiskA*** 以纯风险积分为搜索目标，公共综合代价只在路径返回后统一计算。60 s 和 180 s 下它没有在预算内返回路径；600 s 下四个任务都返回了路径，但综合代价高于 RC-A*，路径也更长。这个结果说明 RiskA* 的纯风险目标和综合代价判据并不相同，适合作为风险最小化基线，而不是当前综合代价 winner。

**RRT*** 在多个条件下找到了合法路径，但严格 `success` 数仍较少。600 s 下四个条件的严格成功数为 0/20，合法路径发现数为 10–16/20；已有路径综合代价中位数约为 803–836，高于 RC-A*。延长预算提高了路径发现数量，但采样算法仍未达到 80% 成功率门槛。

**Informed RRT*** 的表现和 RRT* 接近。600 s 下它在 A/2 有 7/20 个严格成功，在 A/1、B/1、B/2 分别有 5/20、4/20、2/20；合法路径发现数为 12–16/20。椭球采样改善了部分条件的成功数量，但整体仍低于 80% 门槛，不能参与正式最优排名。

### 6.3 不同情况下的算法选择建议

按当前数据，可以给出以下选择规则：

1. **任务 1 或跨高度任务 3，预算较短且需要稳定结果时，优先 RC-A***。在 A、B 两个场景的 60 s 和 180 s 结果中，RC-A* 都找到了合法路径，综合代价也低于 A*。
2. **任务较简单、需要尽快得到一条路径时，可以选择 A***。例如 A/1 的 A* 运行时间为 13.1 s，短于 RC-A* 的 21.1 s；B/1 中 A* 运行时间为 58.5 s，RC-A* 为 34.1 s，说明具体速度仍受地图搜索结构影响。
3. **任务 2 需要较长预算时，优先 RC-A***。在 180 s 下，RC-A* 完成了 A/2 和 B/2；在 600 s 下它仍比 A* 更快完成 B/2，综合代价也更低。
4. **需要研究低风险路径或比较采样收敛时，再使用 RiskA*、RRT* 和 Informed RRT***。RiskA* 适合作为纯风险基线；RRT* 和 Informed RRT* 适合分析随机性和预算影响。当前采样算法成功率仍低于 80%，不把它们作为该条件的最终最优算法。

### 6.4 两套地图上的结论是否一致，为什么

两套地图在当前已经可排名的条件下给出了相同的选择结果：60 s 的 A/1、A/3、B/1、B/3，180 s 的 A/1、A/2、A/3、B/1、B/2、B/3，以及 600 s 的 A/1、A/2、B/1、B/2，winner 都是 RC-A*。因此，**“RC-A* 在当前统一综合代价下表现最好”这一结论在 A、B 两套地图和三个预算档位上是一致的**。

两套地图的运行难度和采样结果并不完全相同。B 的建筑体素占比为 9.58%，高于 A 的 3.33%，所以 B/1 的 A* 运行时间达到 58.5 s，而 A/1 只有 13.1 s。B 的风险场高低区域对比度也更强，采样算法在不同任务中的路径发现数会变化。A、B 仍然得到相同 winner，主要是因为 RC-A* 和 A* 在当前成功条件下都能找到接近直线的合法路径，而 RC-A* 的风险加权代价在相同几何路径附近略有优势；地图差异更多反映在运行时间和采样可行率上。

这四点回答了任务书的核心问题：最优算法在当前可排名条件中没有改变，但预算会改变任务能否完成；RC-A* 在已完成条件中综合代价最低；A* 适合较快的简单搜索，RC-A* 更适合较难任务；A、B 两套地图的阶段性 winner 一致，但运行难度和采样算法表现存在明显差异。

## 7. 实验总结与改进

现有数据说明，场景和任务都会影响算法表现。60 s 下，A* 和 RC-A* 能完成任务 1、3，但任务 2 没有在预算内完成；延长到 180 s 后，RC-A* 又完成了 A/2 和 B/2，并继续完成 A/3、B/3。这个变化说明运行预算会直接影响图搜索能否及时给出结果。

两种采样算法在已完成条件中找到过合法路径，但总体成功率仍低于 80% 参与排名门槛。600 s 下，RRT* 的合法路径发现数为 10–16/20，Informed RRT* 为 12–16/20；它们的严格 `success` 数仍然有限。RiskA* 在 600 s 下已经能够返回路径，但综合代价仍高于 RC-A*。

服务器 600 s 任务 1/2 批次已经完整，结果支持前面的阶段性结论。任务 3 尚未在服务器上运行，因此跨高度任务目前使用本地 60 s 和 180 s 结果。后续如果需要完整的长预算三维矩阵，只需单独运行服务器任务 3，不需要重复任务 1/2。
