# R 校验容差决策

## 容差决策摘要

时间区间修正后的 A/B 单窗口最大相对误差为 `3.169514e-5` / `3.170661e-5`，前五探针最大相对误差为 `3.162134e-5` / `3.162518e-5`。这些结果高于 README 的 `1e-5` 阈值，仍是 `MISMATCH`。工程决定以约 `3.17e-5` 作为继续推进的工程容差；这是容差接受，不代表严格校验通过，也不修改代码中的 README 阈值。

工程影响评估认为，该误差对五算法综合代价排名可忽略，五算法差异通常在百分比量级。全量 R 生成和结果报告应保留表述：“R 校验最大相对误差 3.17e-5，已排除已测代码侧原因，来源暂归为基准端未公开口径，不影响算法相对比较。”该影响判断作为工程决策记录，不将现有 MISMATCH 写成 PASS。

## 已排除原因与证据

- `t2` 求解精度：当前固定 80 次二分后达到 binary64 精度附近，增加 4/7 次迭代不改变结果；`t2` 改变 `1e-6 s` 对最终 R 的相对影响约 `1.06e-8`。
- 第二阶段初值连续性：强制将第二阶段初值与第一阶段末速度连续，会把 A 首探针误差扩大到约 `9.677e-3`，不是当前约 `3.17e-5` 残差的解释。
- 垂直速度分支：当前速度比大于 1，使用 coth 实数分支；强制 tanh 会超出实数定义域。
- 常数浮点精度：config 常数以 Python binary64 计算，显式转 binary64 的敏感性结果不变；源码计算中未发现固定小数位舍入或截断。
- P_s：A/B 全局、窗口、探针对照均为 `ALL PASS`。
- 索引与 NaN 语义：index 列出的文件齐全、探针索引列可读，首窗口 NaN 位置不一致数均为 0；已检查的局部索引/NaN 语义没有解释当前残差。由于 `city.npz` 没有完整 R，完整矩阵范围核验仍需由全量校验模式执行。
- 巡航速度 23 m/s：A 首探针相对误差从 `3.162134e-5` 升至 `6.628958e-3`；首窗口前十点平均误差从 `2.372675e-5` 升至 `2.240588e-2`，10 点全部变差。此敏感性结果支持工程采用任务书/config 的 20 m/s；20 m/s 结果仍超过 `1e-5`。

## 全量 R 生成前待确认的输入和基准

- 使用配置唯一来源 `lib/03_场景/config.json`，并固定配置快照；场景输入只读使用 A/B 的 `city.npz`，包括 `building_mask`、`building_footprint`、`pop_density` 与元数据。
- 对照基准只读使用各场景 `slices/summary.json`、`index.json`、全部 `win_*.npz` 和完整 `probe_points.csv`；确认窗口文件清单与索引一致，保留基准文件原状。
- README 规定窗口和探针阈值为 `1e-5`，工程容差说明单独保留在 `assumptions.md` 与报告中。基准端的中间浮点精度、舍入规则和常数版本未说明，后续若获得生成端材料应回填并重新全量校验。
