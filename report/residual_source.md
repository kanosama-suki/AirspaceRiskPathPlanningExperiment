# R 残差来源诊断

诊断范围：A/B 首个 `win_h030_highrisk.npz` 日志中列出的前 10 个失败点，以及 `probe_points.csv` 前 5 个探针；只读取已有文件，并在内存中对 A 首探针做敏感性复算。当前逐点阈值仍为 `1e-5`。

## 1. 是否纯比例

表中正向比值为“重算值 / 基准值”，反向比值为“基准值 / 重算值”；标准差按总体标准差计算。窗口仅统计日志列出的前 10 点，探针统计前 5 点。

|---|---:|---:|---:|---:|---|---:|---:|
| A 窗口前 10 点 | 10 | 1.00001501205–1.00003166543 | 1.00002372675 | 6.03654e-06 | 0.999968335578–0.999984988171 | 0.999976273845 | 6.03625e-06 |
| A 探针前 5 点 | 5 | 1.00001357569–1.00003167854 | 1.00002668795 | 7.05551e-06 | 0.999968322462–0.999986424492 | 0.999973312810 | 7.05518e-06 |
| B 窗口前 10 点 | 10 | 1.00003059089–1.00003170070 | 1.00003153582 | 3.17897e-07 | 0.999968300306–0.999969410047 | 0.999968465175 | 3.17877e-07 |
| B 探针前 5 点 | 5 | 1.00001353146–1.00003162518 | 1.00002390103 | 7.78174e-06 | 0.999968375823–0.999986468722 | 0.999976099599 | 7.78139e-06 |

结论：不是严格纯比例。整体是重算值略高于基准值的系统性小偏差；B 窗口这 10 点接近同一比例，A 窗口与两组探针的比例散布更明显。

本次样本的高度全部为 `h_idx=0`（`z=30 m`），因此不能用这些点判断误差是否随高度变化。各组误差与输入项的描述性 Pearson 相关如下；每组仅 5 或 10 点，不能据此作总体统计推断：

| 场景/样本 | P_s 范围 | population density 范围 | 相对误差与 P_s 相关 | 与人口密度相关 | 与基准 R 大小相关 |
|---|---:|---:|---:|---:|---:|

| B 窗口前 10 点 | 0.1587–0.6122 | 0.0381103–0.0402804 | -0.92238 | 0.51077 | 0.96588 |

在这四组抽样中，相对误差都随 P_s 增大而下降；人口密度相关的方向不一致，不能说明存在稳定的人口密度效应。基准 R 大小相关也不一致。高度没有变化，无法检验高度效应。

## 2. t2 精度

`parachute_impact_components()` 用括区间二分求解撞地时刻：初始下界为 `t1`，上界为 `t1 + 1 s`；若上界处垂直位移仍不足，则从 `t1` 起将区间宽度逐次加倍。随后固定迭代 80 次，每次取区间中点。没有 Newton 法、显式绝对/相对容差，也没有可配置初值；初始试探点是首个区间中点。

A 场景第一个探针（`i=82, j=444, h_idx=0`）结果：

- 当前 `t2 = 7.143109489629861 s`；80 次后括区间宽度为 `8.881784197001252e-16 s`，已到 binary64 浮点间距量级。
- 源码没有可直接收紧 10 倍/100 倍的容差参数。作为诊断代理，在 80 次基础上增加 4 次和 7 次二分（理论上分别将区间再缩小 16 倍和 128 倍），`t2` 均未改变，面积和 R 也未改变。
- 将当前 `t2` 人为增加 `1e-6 s`：`A_c,p` 改变 `-2.2504807795e-08 m²`（相对变化 `-1.16601e-08`）；最终 R 改变 `-4.2492287195e-18`（相对变化 `-1.05775e-08`）。

判断：当前根求解精度远足以排除 `3e-5` 量级的残差。注意“迭代数代理”不是源码中不存在的容差设置。

## 3. 初值连续性

A 首探针第一阶段结束速度和第二阶段在 `t=t1` 处的速度：

| 分量 | 第一阶段末 `v1(t1)` | 第二阶段 `v2(t1)` | 差值 `v2-v1` |
|---|---:|---:|---:|
| 水平 `v_x` (m/s) | 19.336749492410327 | 2.3477530026038362 | -16.988996489806491 |
| 垂直 `v_y` (m/s) | 6.833223596959251 | 4.362027865381410 | -2.471195731577842 |

第二阶段用第一阶段末速度构造参数，但代码用全局时间 `t` 代入速度表达式；没有把水平、垂直速度表达式的时间自变量平移为 `t-t1`。垂直位移则通过减去 `t1` 时刻的原语值来计算阶段位移。因此速度在阶段连接处不连续，不能说第二阶段在 `t1` 处严格以第一阶段末速度为初值。

敏感性检验中，将第二阶段两分量改按经过时间 `t-t1` 演化、并令连接点速度等于第一阶段末速度，得到 `A_c,p=1.9505984769157525 m²`，最终 R 相对误差 `9.67711998e-03`。这比当前 `3.16213403e-05` 大得多。故代码存在初值连续性差异，但“强制连续”候选不能解释或消除当前残差；时间变量定义仍应由公式原文/基准生成口径确认。

## 4. 垂直速度分支

源码分支条件为：先判断 `math.isclose(v1_y / v_p, 1.0, rel_tol=1e-12, abs_tol=0.0)`；否则比值 `< 1` 时走 `tanh/arctanh`，比值 `> 1` 时走 `coth/arccoth`。

A 首探针中，第一阶段末垂直速度 `v1_y=6.833223596959251 m/s`，开伞终端垂直速度 `v_p=4.281501814003186 m/s`，比值 `1.595987551519969`，因此当前走 `coth` 分支。强制改走 `tanh` 时需计算 `atanh(1.59598755...)`，超出实数定义域并触发 `ValueError: math domain error`；没有可报告的实数 `A_c,p` 或最终 R。

判断：分支切换不是小幅数值扰动；当前物理参数下另一个候选分支无实数解，不能用它估计 `3e-5` 的误差变化。

## 5. 数值精度与常数

A 首探针调用链中的参数来自 `config.json`，经 `float(...)` 后以 Python `float`（IEEE-754 binary64）计算：

| 参数 | config 值 | 来源键 | `float()` 后 `.17g` 往返表示 | 运行时类型 |
|---|---:|---|---:|---|
| m | 9.2 kg | `table1.MASS` | 9.1999999999999993 | Python float / binary64 |
| g | 9.8 m/s² | `table1.G` | 9.8000000000000007 | Python float / binary64 |
| ρ | 1.225 kg/m³ | `supplementary.RHO` | 1.2250000000000001 | Python float / binary64 |
| C_dp | 1.1 | `supplementary.C_D_P` | 1.1000000000000001 | Python float / binary64 |
| S_p | 7.3 m² | `supplementary.S_P` | 7.2999999999999998 | Python float / binary64 |
| T_1 | 0.7 s（代码按秒传入运动学） | `supplementary.T_1` | 0.69999999999999996 | Python float / binary64 |
| r_p | 0.3 m | `supplementary.R_P` | 0.29999999999999999 | Python float / binary64 |
| r_u | 0.45 m | `supplementary.R_U` | 0.45000000000000001 | Python float / binary64 |
| h_p | 1.8 m | `supplementary.H_P` | 1.8 | Python float / binary64 |

实际输入/输出数组类型：A/B 的 `pop_density` 为 `float32`，P_s 计算场为 `float64`，参考窗口 `R_win` 为 `float32`。Python 对人口密度标量转成 `float` 只会提升其已存储的 float32 数值，不会恢复源数据中不存在的额外位数。

开伞运动的位移使用解析表达式；没有数值积分步长。`t2` 只通过上述二分法求解。`risk_matrix.py` 的中间计算未发现固定小数位舍入或截断；验证器将值格式化为 `.12e` 只影响日志显示。README 记载探针 `R_expected` 使用 `%.10e` 文本格式、窗口 `R_win` 为 float32：这类基准存储/文本量化比当前残差小得多，不能单独解释 `3e-5`。

## 6. 基准生成端口径

README / slices README 可确认的事实：

- `R_win` 存在 NPZ 中，dtype 为 `float32`，形状为 `(64,64)`。
- 探针 `R_expected` 是浮点字面量，格式为 `%.10e`。
- README 允许的窗口和探针逐点相对误差阈值均为 `1e-5`。
- README 说 A/B 共用一份 `config.json`；但没有说明基准生成程序实际是否逐项使用了当前 config 的同一组常数。

README 和 slices 说明未给出基准生成端的浮点中间精度、`t2` 求解器类型/容差、是否在写出前做额外舍入、是否做 smoothing 或插值。README 未说明，无法从现有材料判断。当前仓库中也未找到负责生成这些 `slices` 参考值的脚本，因此无法对这些口径做实证比对。

## 7. 候选敏感性表

A 首探针的基准值为 `4.017118027100e-10`，当前重算值为 `4.017245053756e-10`。固定当前其他风险项、由该探针基准 R 反推得到 `A_c,p` 基准约 `1.9300099189190218 m²`。表中同时给出 `A_c,p` 相对误差和最终 R 相对误差；是否低于 `1e-5` 按最终 R 判断。

| 设置 | `A_c,p` (m²) | `A_c,p` 相对误差 | 最终 R 相对误差 | 低于 `1e-5`？ |
|---|---:|---:|---:|---|
| 当前 80 次二分 | 1.9300771949061797 | 3.48578e-05 | 3.16213e-05 | 否 |
| `t2` 精度代理：80+4 次（区间理论再缩小约 16 倍） | 1.9300771949061797 | 3.48578e-05 | 3.16213e-05 | 否 |
| `t2` 精度代理：80+7 次（区间理论再缩小约 128 倍） | 1.9300771949061797 | 3.48578e-05 | 3.16213e-05 | 否 |
| 所有 config 常数显式转 binary64、使用完整精度 | 1.9300771949061797 | 3.48578e-05 | 3.16213e-05 | 否；与当前相同 |
| 强制第二阶段连接初值等于第一阶段末速度（两分量均按 `t-t1` 演化） | 1.9505984769157525 | 1.06676e-02 | 9.67712e-03 | 否 |
| 强制 `tanh` 分支 | 无实数结果 | 不可计算 | 不可计算 | 否；超出实数定义域 |

没有一个候选把最终 R 误差降到 `1e-5` 以下。强制初值连续的候选恢复到约 `9.68e-3` 的大偏差；加密二分和显式 binary64 不改变当前结果。

## 8. 结论

- **是否纯比例：** 否。正向比值在约 `1.00001353–1.00003170` 间变化；但在抽样中普遍是重算值略高，且相对误差与 P_s 呈明显负相关。所有抽样均在 30 m 层，无法评估高度效应。
- **最可能的残差来源排序：**
  1. `A_c,p` 相关的第二阶段水平速度/时间原点/撞击速度定义或基准生成公式细节。A 首探针固定其他项反推的面积比当前小 `6.72760e-05 m²`；对应 `d_p` 差约 `4.48507e-05 m`。这是直接能解释 P_s=0 探针残差的量级，但目前不能据此确定应修改哪种公式口径。
  2. P_s 参与致死率/缓解链后的非线性差异或基准端未记录的公式/参数口径；相对误差随 P_s 变化，人口密度相关方向不一致。
  3. 基准生成程序未记录的中间精度、常数和预处理约定。已知输出存储/探针文本精度本身不足以解释当前误差；未说明的基准生成口径仍无法排除。
  4. `t2` 二分精度、Python binary64 或固定小数截断。敏感性结果与它们作为主要来源不符。
- **哪个候选能低于 `1e-5`：** 本次测试的候选都不能；不得视为通过，也不应放宽阈值。
- **仍需人工确认：** 论文式 (19)–(21) 的第二阶段时间自变量及初值定义、伤亡距离究竟按撞击瞬时速度比还是位移口径实现，以及参考切片生成端使用的常数/公式与预处理。当前 coth 分支由 `v1_y/v_p>1` 决定，强制 tanh 在实数域无效。
